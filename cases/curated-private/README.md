# 自有設計規格的離線驗收案例

這 18 題各自取自一份經作者授權使用的設計規格。每題選一個可獨立觀察的行為，附合成輸入及預期結果，讓不同 agent 面對相同問題。題目處於候選狀態。指定為實驗前，由人確認觀察指標及通過條件。

| 題號 | 問題 | 題號 | 問題 |
| --- | --- | --- | --- |
| [P01](#p01) | 接收中斷的工作如何續跑 | [P02](#p02) | 辨識服務滿載時的行為 |
| [P03](#p03) | 重送上傳請求只保留一次容量 | [P04](#p04) | 切換規則時，進行中的工作讀哪個版本 |
| [P05](#p05) | 交付結果未知時的對帳 | [P06](#p06) | 離線檢查主機基線漂移 |
| [P07](#p07) | 哪些遙測欄位可以用來分組 | [P08](#p08) | 完成聲明有沒有證據 |
| [P09](#p09) | 有子任務、缺值時怎麼算用量 | [P10](#p10) | 交付報告的證據連結可否重查 |
| [P11](#p11) | 分辨重送紀錄與同額消費 | [P12](#p12) | 兩台裝置編輯同份筆記 |
| [P13](#p13) | 不完整的目錄掃描能否判定檔案消失 | [P14](#p14) | 轉寄器辨認自己的輸出 |
| [P15](#p15) | 檔案搬移計畫在確認後才執行 | [P16](#p16) | 會過期的檔案索引 |
| [P17](#p17) | 人取回互動工作階段的控制權 | [P18](#p18) | 把既有服務登記成可查詢的目錄 |

每個指紋均為固定版本原文 UTF-8 位元組的 SHA-256，供持有原文的授權審查者核對。例中使用的帳號、資料與外部服務均可由測試替身提供。

<a id="p01"></a>

## P01　接收中斷的工作如何續跑

工作來源以通道、帳號、外部事件 ID 共同識別。用記憶體或暫存檔模擬收到、分類、規劃三步，交付事件清單和可重建的最後狀態。

1. 同一份合成事件送兩次，只有一個工作 ID 和一組事件。
2. 同一來源鍵改用不同內容，回傳衝突，原紀錄逐位元相同。
3. 預先只存到「收到」，重送後只補缺少兩步；從空白狀態重播取得相同結果。

來源指紋 `9f1638b673e565b8f07a19250bb0f2ae1188b1647cf32ce0e1ccd6721f5c94bf`。

<a id="p02"></a>

## P02　辨識服務滿載時的行為

用假辨識引擎與可計數的請求本文模擬 OCR 服務。工作者可以維護固定數量的執行與等待名額。交付結果碼、讀取本文次數和引擎呼叫次數。

1. 探查程序存活時，引擎呼叫數為 0。
2. 名額全部占滿，再送一張合成圖片，回傳 503，讀取本文與引擎呼叫數皆為 0。
3. 已取得名額但等候逾時，回傳 503；後續請求能取得釋出的名額。

來源指紋 `8c09864b7f220f55ab0262fbdbdbdc4e5749b7f5c8fa97634e17d7b895868940`。

<a id="p03"></a>

## P03　重送上傳請求只保留一次容量

用兩個虛構裝置、固定時鐘與記憶體容量表建立分段上傳工作。查驗回傳的工作身分、到期時間和保留容量。

1. 同一裝置使用同一鍵重送同一份建立請求，回傳相同上傳 ID、物件 ID、分段大小及到期時間，容量只保留一次。
2. 同一鍵改用不同大小，回傳衝突，既有保留不變。
3. 第二個裝置查詢或取消第一個裝置的未完成上傳，得到不存在時相同的結果，原上傳仍可續跑。

來源指紋 `b1cd62a7b52ffd0650901917f5d28b80949f6b13aae29ea61671df417d48be68`。

<a id="p04"></a>

## P04　切換規則時，進行中的工作讀哪個版本

用兩份合成規則 A、B 模擬候選、批准與啟用。每個工作開始時固定讀取一個快照。交付指標狀態與有序事件。

1. A 正在使用。提交格式無效的 B 時，當前版本、候選及歷史紀錄均維持原狀。
2. 尚未批准的 B 不能啟用；成功批准與啟用應各留下事件，順序可查。
3. 工作甲在切換前取得 A；切換後甲仍讀 A，新工作乙只讀 B。

來源指紋 `213a387a923ff3f86030eab744d87e1e0785258308a0d08ad3a8b31ceb63f079`。

<a id="p05"></a>

## P05　交付結果未知時的對帳

以假接收端處理有穩定 ID 的輸出。輸入一份工作及兩項待送資料，模擬程序在接收端可能已套用後中斷。交付狀態及外部呼叫紀錄。

1. 工作與兩項輸出一起落盤。重送相同工作回原收據並維持兩項，有相同 ID 但內容不同則回衝突。
2. 重新啟動後，把結果不明的輸出列為待對帳；在對帳前，傳送次數維持原值。
3. 查到已套用時標成功，確認未套用時以同一輸出 ID 進入待送，仍不明時維持待對帳。

來源指紋 `7cda4d84dad1aae5ff14df1f4b842401520f179a56b6c55e64f2c955e78f107a`。

<a id="p06"></a>

## P06　離線檢查主機基線漂移

用純資料表表示受管目錄和服務啟用狀態，實作預覽、套用與修復。所有操作限於測試用狀態表。

1. 從缺一個受管目錄的初始狀態預覽，只列需新增的目錄，輸入保持相同。
2. 套用後再預覽，變更清單為空。
3. 將受管服務改為停用，再修復，服務恢復；額外加入的非受管項目原樣保留。

來源指紋 `c2a4fc71aadcfc621aaf597a3e9594dc9561e617bd121029efc82b39a7edbcf3`。

<a id="p07"></a>

## P07　哪些遙測欄位可以用來分組

用合成事件檢查遙測資料契約。服務名稱可作統計維度，單次請求、使用者、事件及追蹤 ID 不可作統計維度；追蹤關聯仍可保留在允許的事件欄位。

1. 對有效事件，服務名稱可分組、可保留追蹤關聯；聚合鍵中找不到該追蹤 ID。
2. 送入含模擬敏感欄位的有效事件，輸出去除指定秘密欄位、遮蔽指定個資欄位。
3. 畸形事件進隔離清單，其餘有效事件仍可處理；檢查記錄中無模擬敏感值。

來源指紋 `9fc1b114a2e2b7f40d5f41251679f56fd996a2f049179fbb77bbd498ee9c4978`。

<a id="p08"></a>

## P08　完成聲明有沒有證據

用本機命令檢查 worker 的合成任務單與交付報告。任務 ID、必填欄位、狀態與已執行的必要檢查都要能判讀。

1. 欄位齊全、ID 合法且必要驗證都有成功證據的報告通過。
2. 拿掉一個必填欄位或使用未知狀態，結束碼非零，說明指出問題。
3. 把必要驗證標成跳過或失敗，報告仍聲稱完成時驗證失敗；輸出保留未通過的檢查。

來源指紋 `518e0978eca656827137132a36c6d2627cd190a2a7ff3b94bd8990e5518d54bf`。

<a id="p09"></a>

## P09　有子任務、缺值時怎麼算用量

給定合成執行樹、增量觀測及累計快照，輸出每個節點自身與含後代的用量，保留未知欄位。

1. 父節點有 10 個已觀測 token，子節點有 7 個；父節點含子合計為 17。另有顯示 10 的累計快照時，結果仍是 17。
2. 加入用量未知的另一個子節點，該欄顯示下限 17 並標記不完整。
3. 父節點不存在的紀錄獨立標示；兩個節點互指時回報循環，不加總該分量。

來源指紋 `03546fea2ce5b67c00ccab029e84377ab1f3cdb5538e1bfa522b8daf43029e09`。

<a id="p10"></a>

## P10　交付報告的證據連結可否重查

在合成暫存目錄建立報告與少量證據檔。掃描報告中提出的相對路徑及可選 SHA-256，交付逐項結果。

1. 存在的普通檔案，雜湊一致或未指定雜湊時為 `ok`；結果不含檔案本文。
2. 不存在為 `missing`，雜湊錯誤為 `hash_mismatch`，兩種狀況均使總結束碼為 1。
3. 指到允許目錄外的連結或遠端網址為 `rejected`，不讀取目標；全數 `ok` 時結束碼為 0。

來源指紋 `086c2238aadc8def901b06dd894a189acc3d1c9ac1ffc8f2e5ed13ab274d6f5c`。

<a id="p11"></a>

## P11　分辨重送紀錄與同額消費

用三份自編文字收據驗證擷取後的金額、原始紀錄身分及候選分組。所有日期、商戶與金額皆為測試資料。

1. 原文只載 10.00，擷取結果給 18.00 時，整筆拒絕。
2. 同一封合成收據重送，用同一筆來源引用更新，帳本只有一列。
3. 不同收據碰巧同日、同商戶、同幣別、同額時，兩筆各自保留，可提示同組供人複查。

來源指紋 `40110a15b35df2a3269a78751e89e8ba0faf10a1f2c02ccf1c73ae1ad47b3eaa`。

<a id="p12"></a>

## P12　兩台裝置編輯同份筆記

用兩份本機快照扮演兩台裝置，存一筆有 ID、版本、正文、標籤與狀態的合成筆記。交付保存、衝突及還原結果。

1. 甲離線保留草稿，乙先寫入新版；甲上線時提示版本衝突，甲草稿與乙新版都可取回。
2. 從正常版本匯出，再還原到空資料夾，ID、正文、狀態、標籤和版本一致。
3. 未獲授權的角色直接讀取或匯出，得到拒絕，結果不含正文。

來源指紋 `3ba6dd832b3206191a691a39592789bb60a9406f3cd8f71a4a8544fc7f42cde7`。

<a id="p13"></a>

## P13　不完整的目錄掃描能否判定檔案消失

用分頁的假目錄服務提供一個根節點、兩個子目錄及數個檔案。依深度限制掃描，保存頁面及斷點。

1. 深度 0 僅含根；深度 1 含直接子項，未能涵蓋完整子樹的總量標為部分統計。
2. 上次見過的檔案在本次掃描未列出，但父目錄仍有分頁失敗時，保留舊紀錄。
3. 下次成功完成相關父目錄及整次掃描，確認檔案缺失才標記移除；其既有註記仍可查。

來源指紋 `c144cfa403fb6f99dbcfb2382f2031f2e347582e5fbee1289b1c6348eaeb13f9`。

<a id="p14"></a>

## P14　轉寄器辨認自己的輸出

給定普通文字與 HTML 形式的合成郵件，在離線程序中執行防迴圈及正規化，不建立真實連線。交付選取原因與文字輸出。

1. 寄件者等於設定的轉寄端、帶轉寄信封標記或主旨帶保留前綴，三種情境分別記錄為 `loop_guard` 並跳過。
2. 同一信同時有純文字與 HTML 時，取純文字。
3. 僅有 HTML 時移除樣式與腳本，不請求遠端圖片。連結保留顯示文字及網域，捨棄完整網址中的查詢字串。

來源指紋 `6c72bb5238c68dc9b196eaafe6696e0e9ed95dc8d41363fecd59f6407df76b94`。

<a id="p15"></a>

## P15　檔案搬移計畫在確認後才執行

以記憶體檔案樹及假檔案介面建立搬移清單。預覽只讀屬性與目錄；啟動前重新計算計畫摘要。

1. 預覽同時選取目錄及其子檔時回報重疊，未發出寫入或搬移呼叫。
2. 合法樹含空目錄，計畫保留目錄，保存摘要。同一份已確認的計畫重送，取得相同執行 ID。
3. 如果已確認摘要與要執行的計畫不一致，阻擋執行；目標端同名檔即使同大小，也不能只比大小便跳過完整驗證。

來源指紋 `61c10b5493a899d13c93728d3265d00f32a26baba1816b0755080448344f4efb`。

<a id="p16"></a>

## P16　會過期的檔案索引

用固定時鐘與假的附件事件串流建暫存索引，包含兩次重送的上傳通知及一筆將到期的附件。交付索引筆數與讀取結果。

1. 上傳已建立一筆，後續同步讀到該訊息 ID 和檔案 ID，仍只有一筆。
2. 到期以前可讀取；跨過到期時間後，即使延後清理尚未執行，讀取已回 404。
3. 到期後觸發列表清理，該筆不再列出；既有未到期項目仍可見。

來源指紋 `e3d0a177d14810cf2fc6d9c9052ece0140224ef1a191ff88a9df158a6e46e4ed`。

<a id="p17"></a>

## P17　人取回互動工作階段的控制權

用假顯示器及輸入事件模擬 agent 正操作、人要求接管、舊輸入仍在排隊的過程。交付權限轉移時間序與實際收到的輸入。

1. 人要求接管後，先顯示正在接管，待 agent 輸入停止才交給人。
2. 延後抵達的舊輸入不能改動顯示器；此限制由程式強制。
3. 接管前後對話與顯示工作階段 ID 保持相同，人可在原畫面繼續操作。

來源指紋 `ce48fe8c67315e5a9208b171e74f36f9dce7cea07809ca894176071c22cddf48`。

<a id="p18"></a>

## P18　把既有服務登記成可查詢的目錄

用兩個虛構節點、服務清單與記錄呼叫的假執行器，區分「只登記」與「套用部署」。交付目錄及呼叫順序。

1. 只登記一個已運作服務，目錄有一筆，執行器呼叫為零。
2. 節點仍有服務時，移除節點的動作遭拒。
3. 重複部署同一服務名稱、但版本不同，更新既有項目的產物版本，目錄仍只有一筆。

來源指紋 `e3e95c65ee5c7de2da80b656e947ae100875d94acd1b598cc606d068f085fce0`。

## 來源範圍

盤點涵蓋帳號當時可讀的 23 個私人儲存庫預設分支。11 個儲存庫提供本頁採用的規格。另有 3 個的候選已遷移或與已收錄的同系統版本重疊；3 個主要是研究紀錄、知識筆記或內部流程規範；其餘 6 個在此次以路徑及標題進行的盤點中未發現符合條件的規格。個別產品雖有多份設計稿，這裡按可獨立驗收的行為選題。範圍只涵蓋本次讀取的版本，文件夾中的案例均尚待實驗驗收。
